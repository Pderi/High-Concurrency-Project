---

## 1. 文档目的

本文档描述抢票票务平台首期（票档库存、无选座）在 **MySQL** 中的逻辑模型、表结构、索引与约束，为《系统设计》与编码实现提供数据库层基线。  
**不包含**：Redis Key 设计、分库分表路由规则（可在技术方案中另述）。

---

## 2. 设计原则

| 原则 | 说明 |
| --- | --- |
| 模块前缀 | 业务表统一使用前缀 `tkt_`（ticket 模块缩写），与规范中 `module_` 示例一致。 |
| 主键 | 业务表主键均为 `BIGINT` 自增 `id`（分布式 ID 策略可在实现期替换为雪花等，表结构兼容 BIGINT）。 |
| 金额 | 单价、总价等使用 `INT` 或 `BIGINT`，单位为**分**，避免小数精度问题。 |
| 软删 | 业务表统一 `deleted` 软删除；**订单、库存流水**等审计敏感表是否允许物理删除由实现约定，本设计默认**仅软删或禁止删**。 |
| 多租户 | 预留 `tenant_id`，单租户可固定为 `0`。 |
| 时间 | 使用 `DATETIME`，时区由应用与 MySQL 配置统一（建议 UTC 或业务约定东八区）。 |
| 并发控制 | 票档可售库存以 `tkt_tier` 行为准，扣减采用 **`sold_stock` + `version` 乐观锁** 或与 `WHERE remaining_stock >= ?` 结合；缓存与 DB 对账依赖流水表。 |

## 3. 领域模型与表清单

### 3.1 ER 关系（逻辑）

```text
tkt_show (演出) 1 ── * tkt_session (场次) 1 ── * tkt_tier (票档)
                                      │
                                      ├── * tkt_order (订单)
                                      │         │
                                      │         └── * tkt_ticket (电子票/凭证，支付后生成)
                                      │
tkt_session ── * tkt_stock_ledger (库存流水，可选强一致对账)
```

### 3.2 表一览

| 物理表名 | 说明 |
| --- | --- |
| `tkt_show` | 演出 |
| `tkt_session` | 场次（开售时间、场馆等） |
| `tkt_tier` | 票档（价格、总库存、已售、限购、乐观锁版本） |
| `tkt_order` | 订单（待支付/已支付/已关闭等） |
| `tkt_ticket` | 电子票凭证（支付成功后按张生成） |
| `tkt_stock_ledger` | 库存变动流水（对账、排查热点扣减） |
| `tkt_admin_audit` | 管理端关键操作审计（可选，也可用统一操作日志中间件替代） |

## 4. 枚举与状态（应用层枚举 + DB 存整型）

以下为建议取值，与 `tinyint`/`int` 字段对应；具体以 `*-api` 模块枚举为准。

| 字段域 | 值 | 含义 |
| --- | --- | --- |
| `show_status` | 0 | 草稿 |
| | 1 | 已发布 |
| | 2 | 已下架 |
| `session_status` | 0 | 未开售/草稿 |
| | 1 | 即将开售（已配置） |
| | 2 | 开售中 |
| | 3 | 停售 |
| | 4 | 场次结束 |
| `order_status` | 10 | 待支付 |
| | 20 | 已支付 |
| | 30 | 已关闭（含超时未付、取消） |
| | 40 | 已退款（预留，首期可不实现业务） |
| `pay_channel` | 0 | 未支付 |
| | 1 | 模拟支付 |
| | 2 | 微信（预留） |
| | 3 | 支付宝（预留） |
| `ticket_status` | 0 | 未生效（不应长期出现） |
| | 1 | 有效 |
| | 2 | 已作废/已退票（预留） |
| `stock_change_type` | 1 | 下单预占 |
| | 2 | 支付确认 |
| | 3 | 超时释放 |
| | 4 | 管理端调整 |
| | 5 | 对账修正 |

### 5.3 `tkt_tier` 票档

| 字段名 | 类型 | 空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT | NO | AUTO | 主键 |
| session_id | BIGINT | NO | | 场次 ID |
| tier_name | VARCHAR(64) | NO | | 票档名称，如 VIP、看台 A |
| price_cent | INT | NO | | 单价（分） |
| total_stock | INT | NO | | 总库存张数 |
| sold_stock | INT | NO | 0 | 已售张数（含待支付已占用的数量，见业务规则） |
| per_user_limit | INT | NO | 1 | 单人限购张数 |
| version | INT | NO | 0 | 乐观锁版本号 |
| status | TINYINT | NO | 1 | 1 上架 0 下架 |
| creator | VARCHAR(64) | NO | '' | |
| create_time | DATETIME | NO | CURRENT_TIMESTAMP | |
| updater | VARCHAR(64) | NO | '' | |
| update_time | DATETIME | NO | CURRENT_TIMESTAMP ON UPDATE | |
| deleted | TINYINT | NO | 0 | |
| tenant_id | BIGINT | NO | 0 | |

**业务规则（与实现约定）**

- **可售剩余**（逻辑）：`remaining = total_stock - sold_stock`，应用层与缓存侧须与此公式一致。  
- **sold_stock 语义（推荐）**：包含「已占未付 + 已支付」的张数；超时关单时对 `sold_stock` 做减少，并写流水。若采用「待支付不占 sold 而占另一字段」，需在技术方案中拆分字段，本表可扩展 `locked_stock`。

**索引**

- PRIMARY KEY (`id`)
- KEY `idx_tier_session` (`session_id`)

### 5.4 `tkt_order` 订单

| 字段名 | 类型 | 空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT | NO | AUTO | 主键 |
| order_no | VARCHAR(32) | NO | | 业务订单号，全局唯一 |
| user_id | BIGINT | NO | | 用户 ID |
| session_id | BIGINT | NO | | 场次 ID |
| tier_id | BIGINT | NO | | 票档 ID |
| quantity | INT | NO | | 购买张数 |
| unit_price_cent | INT | NO | | 下单时单价快照（分） |
| total_amount_cent | INT | NO | | 应付总金额（分） |
| order_status | TINYINT | NO | 10 | 见 `order_status` |
| pay_channel | TINYINT | NO | 0 | 见 `pay_channel` |
| pay_time | DATETIME | YES | NULL | 支付成功时间 |
| pay_deadline | DATETIME | NO | | 支付截止时间 |
| close_reason | VARCHAR(64) | YES | NULL | 关闭原因：timeout/cancel/… |
| idempotency_key | VARCHAR(64) | YES | NULL | 客户端幂等键；空则仅依赖服务端防重 |
| creator | VARCHAR(64) | NO | '' | 下单人（可与 user_id 对应） |
| create_time | DATETIME | NO | CURRENT_TIMESTAMP | |
| updater | VARCHAR(64) | NO | '' | |
| update_time | DATETIME | NO | CURRENT_TIMESTAMP ON UPDATE | |
| deleted | TINYINT | NO | 0 | |
| tenant_id | BIGINT | NO | 0 | |

**索引与约束**

- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_order_no` (`order_no`)
- KEY `idx_order_user` (`user_id`, `create_time`)
- KEY `idx_order_session_tier` (`session_id`, `tier_id`)
- KEY `idx_order_pay_deadline` (`order_status`, `pay_deadline`) — 供超时关单任务扫描
- UNIQUE KEY `uk_order_idempotent` (`user_id`, `session_id`, `tier_id`, `idempotency_key`) — **要求 `idempotency_key` 非空时生效**；若 MySQL 版本不支持条件唯一索引，可改为应用层校验 + 普通索引 `idx_order_idem`(`user_id`,`idempotency_key`)

**说明**

- 首期可无独立「支付单」表，支付信息挂在订单上即可。  
- **防超卖**依赖：订单创建成功时对 `tkt_tier` 的原子扣减 + 流水；与 Redis 预扣对齐时在《技术方案》中说明对账逻辑。

### 5.6 `tkt_stock_ledger` 库存流水

用于对账、审计及排查热点扣减问题；**建议首期即建**，避免事后无据可查。

| 字段名 | 类型 | 空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT | NO | AUTO | 主键 |
| tier_id | BIGINT | NO | | 票档 ID |
| session_id | BIGINT | NO | | 冗余 |
| change_type | TINYINT | NO | | 见 `stock_change_type` |
| delta | INT | NO | | 变动张数（正数增加可售、负数扣减按约定；或统一为「sold 变化量」） |
| before_sold | INT | NO | | 变动前 sold_stock |
| after_sold | INT | NO | | 变动后 sold_stock |
| order_id | BIGINT | YES | NULL | 关联订单，管理端调整可为空 |
| remark | VARCHAR(256) | YES | NULL | |
| creator | VARCHAR(64) | NO | '' | 系统或操作者 |
| create_time | DATETIME | NO | CURRENT_TIMESTAMP | |
| tenant_id | BIGINT | NO | 0 | |

**索引**

- PRIMARY KEY (`id`)
- KEY `idx_ledger_tier_time` (`tier_id`, `create_time`)
- KEY `idx_ledger_order` (`order_id`)

**说明**：`delta` 与 `before/after` 的语义须在实现中统一（例如仅记录 `sold_stock` 增加 2 则 `delta=+2`）。

## 6. DDL 参考（MySQL 8.0+）

以下为可直接微调后执行的建表脚本骨架；具体以项目脚手架与字符集策略为准。

```sql
CREATE TABLE `tkt_show` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  `name` VARCHAR(128) NOT NULL COMMENT '演出名称',
  `subtitle` VARCHAR(256) DEFAULT NULL COMMENT '副标题',
  `cover_url` VARCHAR(512) DEFAULT NULL COMMENT '封面',
  `description` TEXT COMMENT '详情',
```

## 7. 核心业务流程与表协作（摘要）

| 流程 | 涉及表 | 说明 |
| --- | --- | --- |
| 抢票下单 | `tkt_tier`（扣减 sold / 乐观锁）、`tkt_order`（插入待支付）、`tkt_stock_ledger` | 与 Redis 预扣一致时，落库后对齐流水 |
| 支付成功 | `tkt_order`（已支付）、`tkt_ticket`（插入 N 行） | 可再记一条 ledger type=支付确认 |
| 超时关单 | `tkt_order`（已关闭）、`tkt_tier`（sold 回退）、`tkt_stock_ledger` | 定时任务扫 `pay_deadline` |
| 管理端改库存 | `tkt_tier`、`tkt_stock_ledger`、`tkt_admin_audit` | 需权限与审计 |

## 8. 与高并发相关的数据库侧要点

| 主题 | 建议 |
| --- | --- |
| 热点行 | `tkt_tier` 按票档为单行更新热点，配合缓存 Lua 预扣 + 异步落库；避免在 `tkt_session` 上高频更新计数。 |
| 乐观锁 | `tkt_tier.version` 与 `UPDATE ... WHERE id=? AND version=?`；失败重试策略在应用层限制次数。 |
| 订单号 | `order_no` 使用分段或雪花，避免自增可预测；唯一索引保证幂等落库。 |
| 超时扫描 | `idx_order_pay_deadline` 仅扫待支付；注意任务分片与批量大小，避免长事务。 |
| 读扩展 | 列表/详情只读可走从库；订单写仍走主库。 |
| 演进 | 订单表数据量大时，可按 `create_time` 分表或归档；与本需求首期无关，预留 `order_no` 全局唯一即可。 |

## 9. 与需求文档的追溯

| 需求要点 | 数据库落点 |
| --- | --- |
| 票档级库存、无选座 | `tkt_tier.total_stock` / `sold_stock` |
| 支付超时释放 | `tkt_order.pay_deadline` + `order_status` + `tkt_stock_ledger` |
| 电子票查询 | `tkt_ticket` |
| 不超卖 | `tkt_tier` 扣减约束 + 唯一订单/幂等键 |
| 管理端 CRUD | `tkt_show` / `tkt_session` / `tkt_tier` |
| 对账 | `tkt_stock_ledger` 与缓存/订单三方对齐 |
