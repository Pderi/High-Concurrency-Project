## 4. 阶段明细

### P0｜本地环境与配置基线

**要做什么**

1. 准备 MySQL 8，执行 `schema-ticket-mysql8.sql`，库名与 `application.yml` 对齐。
2. 准备 Redis；确认应用能连上（可不启 MQ）。
3. 统一本地配置方式：`application-local.yml`（勿提交密钥）或环境变量说明。
4. 用管理端接口造演示数据：演出 → 场次 → 票档（含库存）。
5. （可选）Docker Compose：`mysql` + `redis` +（后续）`rocketmq`。

**交付物**

- 可启动的本地说明（可写在本文档附录或根目录简短 README，按需）
- 一套可复用的演示数据（接口调用顺序或 SQL seed）

**验收**

- `tkt-server` 启动成功；`/actuator/health`、管理端 CRUD、Swagger 可用。

**依赖**：无（当前即可做）

### P1｜C 端只读接口（商品目录）

对齐《设计文档》§6.1 读接口。

| 接口 | 说明 |
| --- | --- |
| `GET /app-api/tkt/show/page` 或 `/shows` | 已发布演出分页（仅 status=已发布） |
| `GET /app-api/tkt/show/get` | 演出详情 |
| `GET /app-api/tkt/session/get` | 场次详情 + 票档列表（价格、余票参考值） |

**要做什么**

1. App Controller + VO（与 Admin 分离，禁止复用管理端改写接口）。
2. 只读 Service：过滤草稿 / 下架；余票可先算 `total_stock - sold_stock`（后续可切 Redis）。
3. （建议）短 TTL 缓存场次详情，减轻读压力。

**验收**

- 未发布演出对 C 端不可见；场次详情含票档价与余票。

**依赖**：P0 有数据

### P2｜抢票主链路（核心）

对齐《技术文档》§5.1、《设计文档》§5.1。

**推荐路径（已定技术方向）**

```text
校验开售/限购/票档上架
  → Redis Lua 预扣 tkt:tier:remain:{tierId}
  → 发 MQ TKT_ORDER_CREATE
  → 返回「受理成功」+ 轮询令牌（或短轮询拿 orderNo）
  → 消费者：幂等 → 事务（插订单 + 更新 sold_stock + 写 ledger）
  → 失败：Redis 回补 / 补偿 Topic
```

**任务拆分**

| 序号 | 任务 | 说明 |
| --- | --- | --- |
| 2.1 | 票档余量 Redis 初始化 | 开售前写入或懒加载；与 DB 对齐 |
| 2.2 | Lua 预扣 / 回补脚本 | 原子扣减；不足直接失败 |
| 2.3 | 抢票 API | `POST .../order/grab`；校验 + 预扣 + 投递 |
| 2.4 | 订单号 / 幂等 | `order_no` 生成；`idempotency_key` + DB 唯一索引 |
| 2.5 | MQ 生产者 | 启用 `mq` profile；消息体对齐设计文档 |
| 2.6 | MQ 消费者实装 | 替换当前骨架 TODO；事务落库 + 流水 `change_type=下单预占` |
| 2.7 | 结果查询 | 客户端按令牌 / 幂等键 / orderNo 查单 |
| 2.8 | 失败补偿 | 落库失败回补 Redis；可选 `TKT_ORDER_COMPENSATE` |

**待拍板（实现前需定一条默认）**

| 项 | 选项 | 建议默认 |
| --- | --- | --- |
| 异步建单返回形态 | A. 受理 + 轮询；B. 同步等 orderNo | **A**（更贴高并发叙事） |
| 票档下架时待支付单 | 允许支付 / 批量关单 | 首期 **允许支付至截止** |

**验收**

- 同票档并发抢票：**不超卖**
- 重复幂等键：**不重复建单**
- Redis 扣减失败时不产生脏订单；落库失败后余量可回补

**依赖**：P1（可读商品）；RocketMQ 本地可用

### P3｜模拟支付与电子票

对齐《设计文档》§5.2。

| 接口 | 说明 |
| --- | --- |
| `POST .../order/{orderNo}/pay` | 模拟支付 |
| `GET .../order/get`、`GET .../order/page` | 我的订单（需用户身份） |
| `GET .../ticket/page` | 我的电子票 |

**要做什么**

1. 支付：校验待支付且未过期 → 订单改已支付 → 写 `tkt_ticket` × quantity（流水类型按业务文档：支付确认，若首期不改 sold 则只记流水语义）。
2. 用户身份：首期可用请求头 `X-User-Id` mock（完整登录可放 P5）。
3. 支付超时分钟数读 `tkt.order.pay-timeout-minutes`。

**验收**

- 支付成功后订单状态正确，电子票张数 = quantity；过期单不可支付。

**依赖**：P2 能产出待支付订单

---

### P4｜超时关单与对账

对齐《设计文档》§5.3、《技术文档》§9。

| 任务 | 说明 |
| --- | --- |
| 4.1 关单 Job 实装 | 扫 `order_status=待支付 AND pay_deadline < now`；小批量事务 |
| 4.2 释放库存 | `sold_stock -= quantity`；ledger `超时释放`；Redis 余量回补 |
| 4.3 分布式锁 | `tkt:job:close-order`，多实例不重复关 |
| 4.4 对账 Job（最小版） | 比对 `sold_stock` 与有效占用；偏差告警或记 `对账修正` 流水 |

**验收**

- 超时单关闭后库存可再被抢；关单有流水；多实例启动不会双倍释放。

**依赖**：P2 / P3 状态机完整

## 6. 风险与依赖

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| RocketMQ 本地成本高 | 阻塞 P2 | 先用 `mq` profile；或短期用同步落库开关做联调，正式路径仍以 MQ 为准 |
| Redis 与 DB 不一致 | 超卖 / 少卖 | 流水 + 关单回补 + 对账；失败路径必须测 |
| 异步返回形态未拍板 | 接口反复改 | 文档默认采用「受理 + 轮询」，变更记入 MEMORY |
| 无真实用户体系 | C 端订单归属 | 首期 `X-User-Id`；P5 再升级 |

## 附录 A｜本地启动（P0）

```bash
# 1) 启动中间件（首次会自动执行 schema + seed）
docker compose up -d

# 2) 可选：复制本地配置
cp tkt/tkt-server/src/main/resources/application-local.yml.example \
   tkt/tkt-server/src/main/resources/application-local.yml

# 3) 启动应用
mvn -pl tkt/tkt-server -am spring-boot:run -Dspring-boot.run.profiles=local
# 或 IDE 启动 TktServerApplication，Active profiles = local
```

| 检查项 | 地址 |
| --- | --- |
| Health | http://localhost:8080/actuator/health |
| Swagger | http://localhost:8080/swagger-ui.html |
| C 端演出分页 | `GET /app-api/tkt/show/page?pageNo=1&pageSize=10` |
| C 端场次详情 | `GET /app-api/tkt/session/get?id=1` |
| C 端抢票 | `POST /app-api/tkt/order/grab`，Header `X-User-Id` |
| 抢票轮询 | `GET /app-api/tkt/order/grab-result?acceptToken=` |

> 若 MySQL 数据卷已存在而种子未生效：`docker compose down -v` 后重建（会清空数据）。
