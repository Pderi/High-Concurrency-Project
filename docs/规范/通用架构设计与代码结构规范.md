## 一、架构设计总览
### 1.1 核心设计理念
#### 1.1.1 高内聚、低耦合
+ **模块内部**：功能高度内聚，各业务域职责清晰
+ **模块之间**：通过API接口和RPC调用实现松耦合交互
+ **分层之间**：通过VO/DTO/DO进行数据传递，避免直接依赖

#### 1.1.2 面向接口编程
+ **API模块**：定义对外暴露的服务契约
+ **Server模块**：实现具体业务逻辑
+ **依赖倒置**：Controller依赖Service接口，Service依赖Mapper接口

#### 1.1.3 分层隔离
+ **表现层**：Controller层，处理HTTP请求
+ **业务层**：Service层，实现业务逻辑
+ **数据访问层**：DAL层，数据持久化
+ **基础设施层**：数据库、缓存、消息队列

#### 1.1.4 可扩展性优先
+ 预留扩展点，支持功能的快速迭代
+ 采用策略模式、工厂模式等设计模式提升灵活性
+ 使用枚举定义可扩展的状态和类型

## 二、模块组织架构
### 2.1 Maven模块结构
采用**Maven多模块**结构，遵循标准的微服务模块组织方式：

```plain
{module-name}/
├── {module-name}-api/              # API接口模块（对外暴露）
│   └── src/main/java/
│       └── com/{company}/{project}/module/{module}/
│           ├── api/                # RPC API接口定义
│           ├── constants/          # 常量定义
│           ├── enums/              # 枚举定义
│           └── service/            # 服务接口（可选）
│
├── {module-name}-server/           # 服务实现模块（业务实现）
│   └── src/main/java/
│       └── com/{company}/{project}/module/{module}/
│           ├── controller/         # 控制器层
│           │   ├── admin/          # 管理端接口
│           │   └── app/             # 小程序端接口
│           ├── service/            # 业务服务层
│           ├── dal/                # 数据访问层
│           │   ├── dataobject/     # 数据对象(DO)
│           │   └── mysql/           # MyBatis Mapper
│           ├── framework/          # 框架配置
│           ├── config/             # 模块配置
│           └── util/               # 工具类
│
└── pom.xml                         # 父POM
```

### 2.2 模块职责划分
#### 2.2.1 API模块 (`{module-name}-api`)
**职责**：对外暴露服务接口，定义模块边界

**核心内容**：

+ **API接口**：供其他模块调用的RPC接口
+ **常量定义**：API常量、错误码常量、日志记录常量、业务域常量
+ **枚举定义**：业务相关的枚举（状态、类型等）
+ **DTO对象**：跨模块调用的数据传输对象

**设计原则**：

+ ✅ 轻量级，只包含接口定义和数据传输对象
+ ✅ 不依赖具体实现，保持模块独立性
+ ✅ 可被其他模块引用而不引入额外依赖

**依赖关系**：

```xml
<dependencies>
    <!-- 只依赖公共模块 -->
    <dependency>
        <groupId>com.{company}.{project}</groupId>

        <artifactId>{project}-common</artifactId>

    </dependency>

    
    <!-- 可选：Swagger注解（provided scope）-->
    <dependency>
        <groupId>org.springdoc</groupId>

        <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>

        <scope>provided</scope>

    </dependency>

</dependencies>

```

#### 2.2.2 Server模块 (`{module-name}-server`)
**职责**：实现业务逻辑，提供完整的服务能力

**核心内容**：

+ **控制器层**：处理HTTP请求，参数校验
+ **服务层**：实现业务逻辑，事务管理
+ **数据访问层**：数据持久化，数据库操作
+ **框架配置**：Security配置、MyBatis配置等

**依赖关系**：

```xml
<dependencies>
    <!-- 依赖自身API模块 -->
    <dependency>
        <groupId>com.{company}.{project}</groupId>

        <artifactId>{module-name}-api</artifactId>

    </dependency>

    
    <!-- 依赖其他模块API -->
    <dependency>
        <groupId>com.{company}.{project}</groupId>

        <artifactId>{other-module}-api</artifactId>

    </dependency>

    
    <!-- Spring Boot Starters -->
    <dependency>
        <groupId>com.{company}.{project}</groupId>

        <artifactId>{project}-spring-boot-starter-web</artifactId>

    </dependency>

    <dependency>
        <groupId>com.{company}.{project}</groupId>

        <artifactId>{project}-spring-boot-starter-mybatis</artifactId>

    </dependency>

    <!-- ... 其他依赖 -->
</dependencies>

```

## 三、分层架构设计
### 3.1 分层架构概述
采用**经典四层架构**，从上到下依次为：

```plain
┌─────────────────────────────────────────────────────────────┐
│                    Controller 层 (表现层)                     │
│  • 接收HTTP请求                                              │
│  • 参数校验                                                  │
│  • 调用Service层                                             │
│  • 返回响应                                                  │
└─────────────────────────┬───────────────────────────────────┘
                          │ VO (View Object)
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Service 层 (业务层)                        │
│  • 业务逻辑实现                                              │
│  • 事务管理                                                  │
│  • 调用DAL层                                                 │
│  • 跨模块RPC调用                                             │
└─────────────────────────┬───────────────────────────────────┘
                          │ DO (Data Object)
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    DAL 层 (数据访问层)                        │
│  • 数据持久化                                                │
│  • 数据库操作                                                │
│  • 缓存操作                                                  │
└─────────────────────────┬───────────────────────────────────┘
                          │ SQL/Cache Key
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Infrastructure 层 (基础设施层)             │
│  • MySQL数据库                                               │
│  • Redis缓存                                                 │
│  • 消息队列                                                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 Controller层设计
#### 3.2.1 职责定义
**核心职责**：

+ ✅ HTTP请求的接收和响应
+ ✅ 参数校验（基于Bean Validation）
+ ✅ 权限校验（基于Spring Security）
+ ✅ 调用Service层处理业务
+ ✅ 异常处理和统一响应

**不应包含**：

+ ❌ 业务逻辑
+ ❌ 数据库操作
+ ❌ 复杂的数据转换

#### 3.2.2 Controller设计规范
**标准模板**：

```java
@Tag(name = "{MODULE} - {业务域}管理")
@RestController
@RequestMapping("/{module}/{domain}")
@Validated
public class {Module}Admin{Domain}Controller {

    @Resource
    private {Domain}Service {domain}Service;

    /**
     * 创建{实体}
     */
    @PostMapping
    @Operation(summary = "创建{实体}")
    public CommonResult<Long> create{Domain}(@Valid @RequestBody {Domain}CreateReqVO createReqVO) {
        return success({domain}Service.create{Domain}(createReqVO));
    }

    /**
     * 更新{实体}
     */
    @PutMapping
    @Operation(summary = "更新{实体}")
    public CommonResult<Boolean> update{Domain}(@Valid @RequestBody {Domain}UpdateReqVO updateReqVO) {
        {domain}Service.update{Domain}(updateReqVO);
        return success(true);
    }

    /**
     * 查询{实体}列表
     */
    @GetMapping("/list")
    @Operation(summary = "查询{实体}列表")
    public CommonResult<PageResult<{Domain}PageRespVO>> get{Domain}List(@Valid {Domain}PageReqVO pageReqVO) {
        PageResult<{Domain}PageRespVO> pageResult = {domain}Service.get{Domain}Page(pageReqVO);
        return success(pageResult);
    }

    /**
     * 获得{实体}详情
     */
    @GetMapping
    @Operation(summary = "获得{实体}详情")
    @Parameter(name = "id", description = "{实体}编号", required = true)
    public CommonResult<{Domain}RespVO> get{Domain}(@RequestParam("id") Long id) {
        return success({domain}Service.get{Domain}(id));
    }

    /**
     * 删除{实体}
     */
    @DeleteMapping
    @Operation(summary = "删除{实体}")
    @Parameter(name = "id", description = "{实体}编号", required = true)
    public CommonResult<Boolean> delete{Domain}(@RequestParam("id") Long id) {
        {domain}Service.delete{Domain}(id);
        return success(true);
    }
}
```

**设计要点**：

1. **RESTful风格**：GET/POST/PUT/DELETE对应查询/创建/更新/删除
2. **统一返回**：使用`CommonResult<T>`统一包装响应
3. **参数校验**：使用`@Valid`和`@Validated`进行参数校验
4. **API文档**：使用Swagger注解生成API文档
5. **Admin/App分离**：管理端和用户端接口分开

### 3.3 Service层设计
#### 3.3.1 职责定义
**核心职责**：

+ ✅ 实现业务逻辑
+ ✅ 事务管理
+ ✅ 数据校验和业务规则校验
+ ✅ 调用DAL层进行数据操作
+ ✅ 跨模块RPC调用

**Service层组织**：

```plain
service/
├── {domain}/
│   ├── {Domain}Service.java             # 接口
│   └── {Domain}ServiceImpl.java         # 实现
└── ...
```

#### 3.3.2 Service设计规范
**标准模板**：

```java
@Service
@Validated
public class {Domain}ServiceImpl implements {Domain}Service {

    @Resource
    private {Domain}Mapper {domain}Mapper;
    
    @Resource
    private {OtherDomain}Service {otherDomain}Service;

    /**
     * 创建{实体}
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public Long create{Domain}({Domain}CreateReqVO createReqVO) {
        // 1. 数据转换
        {Domain}DO {domain}DO = BeanUtils.toBean(createReqVO, {Domain}DO.class);
        
        // 2. 业务校验
        validate{Domain}({domain}DO);
        
        // 3. 保存数据
        {domain}Mapper.insert({domain}DO);
        
        return {domain}DO.getId();
    }
    
    /**
     * 更新{实体}
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void update{Domain}({Domain}UpdateReqVO updateReqVO) {
        // 1. 校验存在
        {Domain}DO {domain}DO = validate{Domain}Exists(updateReqVO.getId());
        
        // 2. 更新数据
        BeanUtils.copyProperties(updateReqVO, {domain}DO);
        {domain}Mapper.updateById({domain}DO);
    }
    
    /**
     * 查询{实体}分页
     */
    @Override
    public PageResult<{Domain}PageRespVO> get{Domain}Page({Domain}PageReqVO pageReqVO) {
        return {domain}Mapper.selectPage(pageReqVO);
    }
    
    /**
     * 获得{实体}详情
     */
    @Override
    public {Domain}RespVO get{Domain}(Long id) {
        {Domain}DO {domain}DO = validate{Domain}Exists(id);
        return BeanUtils.toBean({domain}DO, {Domain}RespVO.class);
    }
    
    /**
     * 删除{实体}
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void delete{Domain}(Long id) {
        // 校验存在
        validate{Domain}Exists(id);
        // 删除
        {domain}Mapper.deleteById(id);
    }
    
    /**
     * 校验{实体}存在
     */
    private {Domain}DO validate{Domain}Exists(Long id) {
        {Domain}DO {domain}DO = {domain}Mapper.selectById(id);
        if ({domain}DO == null) {
            throw exception({DOMAIN}_NOT_EXISTS);
        }
        return {domain}DO;
    }
}
```

**设计要点**：

1. **事务管理**：关键业务使用`@Transactional`
2. **依赖注入**：通过`@Resource`注入Mapper和其他Service
3. **异常处理**：使用自定义业务异常
4. **方法拆分**：复杂逻辑拆分为多个私有方法

#### 3.3.3 Service层依赖规范
**允许的依赖**：

+ ✅ 依赖Mapper（DAL层）
+ ✅ 依赖其他Service
+ ✅ 依赖跨模块API
+ ✅ 依赖工具类

**禁止的依赖**：

+ ❌ 禁止依赖Controller
+ ❌ 禁止依赖VO对象（应使用DO或DTO）

### 3.4 DAL层设计
#### 3.4.1 职责定义
**核心职责**：

+ ✅ 数据持久化
+ ✅ 数据库CRUD操作
+ ✅ 复杂SQL查询
+ ✅ 缓存操作

**DAL层组织**：

```plain
dal/
├── dataobject/              # DO对象
│   ├── {domain}/
│   │   ├── {Domain}DO.java
│   │   └── ...
│   └── ...
│
└── mysql/                   # Mapper接口
    ├── {domain}/
    │   ├── {Domain}Mapper.java
    │   └── ...
    └── ...
```

#### 3.4.2 DO对象设计
**标准模板**：

```java
@TableName("{table_name}")
@Data
@EqualsAndHashCode(callSuper = true)
@ToString(callSuper = true)
public class {Domain}DO extends BaseDO {

    @TableId(type = IdType.AUTO)
    private Long id;

    /**
     * {字段说明}
     */
    private String {fieldName};

    // ... 其他字段
}
```

**设计要点**：

1. **继承BaseDO**：包含creator、createTime、updater、updateTime等公共字段
2. **MyBatis-Plus注解**：`@TableName`、`@TableId`等
3. **Lombok注解**：减少样板代码
4. **字段注释**：清晰的字段说明

#### 3.4.3 Mapper设计
**标准模板**：

```java
@Mapper
public interface {Domain}Mapper extends BaseMapperX<{Domain}DO> {

    /**
     * 查询{实体}分页（管理端）
     */
    default PageResult<{Domain}DO> selectPage({Domain}PageReqVO reqVO) {
        return selectPage(reqVO, new LambdaQueryWrapperX<{Domain}DO>()
                .likeIfPresent({Domain}DO::get{Field}, reqVO.get{Field}())
                .eqIfPresent({Domain}DO::get{Field}, reqVO.get{Field}())
                .orderByDesc({Domain}DO::getCreateTime));
    }

    /**
     * 查询{实体}分页（小程序端）
     */
    default PageResult<{Domain}DO> selectAppPage({Domain}PageReqVO reqVO) {
        return selectPage(reqVO, new LambdaQueryWrapperX<{Domain}DO>()
                .likeIfPresent({Domain}DO::get{Field}, reqVO.getKeyword())
                .inIfPresent({Domain}DO::getId, reqVO.getIds())
                .orderByDesc({Domain}DO::getCreateTime));
    }
}
```

**设计要点**：

1. **继承BaseMapperX**：获得基础CRUD能力和分页能力
2. **default方法**：定义常用查询方法
3. **LambdaQueryWrapper**：类型安全的查询构造
4. **分页支持**：返回PageResult对象

## 五、代码组织原则
### 5.1 单一职责原则（SRP）
**原则**：一个类只负责一项职责

**实践**：

+ Controller只负责请求处理
+ Service只负责业务逻辑
+ Mapper只负责数据访问
+ VO/DO/DTO各司其职

### 5.2 开闭原则（OCP）
**原则**：对扩展开放，对修改关闭

**实践**：

+ 使用枚举定义可扩展的状态
+ 预留扩展接口
+ 使用策略模式支持多种业务场景

### 5.3 依赖倒置原则（DIP）
**原则**：依赖抽象，而不是具体实现

**实践**：

+ Service层定义接口
+ Controller依赖Service接口
+ 跨模块调用通过API接口

### 5.4 接口隔离原则（ISP）
**原则**：客户端不应该依赖它不需要的接口

**实践**：

+ API模块只暴露必要的接口
+ RPC接口粒度合理
+ 避免过度设计

### 7.2 RPC调用设计
#### 7.2.1 API接口定义
**标准模板**：

```java
/**
 * {业务域}API
 * 供其他模块调用
 */
public interface {Module}{Domain}Api {

    String PREFIX = "/rpc/{module}/{domain}";

    @PostMapping(PREFIX + "/create")
    @ApiOperation("创建{实体}")
    CommonResult<Boolean> create{Domain}(@Valid @RequestBody {Domain}CreateReqDTO reqDTO);

    @GetMapping(PREFIX + "/get")
    @ApiOperation("获得{实体}")
    CommonResult<{Domain}RespDTO> get{Domain}(@RequestParam("id") Long id);
}
```

#### 7.2.2 API实现
**标准模板**：

```java
@RestController
@Validated
public class {Module}{Domain}ApiImpl implements {Module}{Domain}Api {

    @Resource
    private {Domain}Service {domain}Service;

    @Override
    public CommonResult<Boolean> create{Domain}({Domain}CreateReqDTO reqDTO) {
        {domain}Service.create{Domain}(reqDTO);
        return success(true);
    }

    @Override
    public CommonResult<{Domain}RespDTO> get{Domain}(Long id) {
        {Domain}RespDTO respDTO = {domain}Service.get{Domain}(id);
        return success(respDTO);
    }
}
```

### 7.3 跨模块调用规范
#### 7.3.1 调用原则
1. **依赖API模块**：只依赖其他模块的API，不依赖实现
2. **接口定义清晰**：API接口定义明确的输入输出
3. **异常处理**：妥善处理RPC调用异常
4. **超时设置**：设置合理的超时时间
5. **降级策略**：关键流程提供降级方案

#### 7.3.2 最佳实践
**✅**** 正确示例**：

```java
@Service
public class {Domain}Service {
    
    @Resource
    private {OtherModule}Api {otherModule}Api;  // 依赖API接口
    
    public void create{Domain}({Domain}CreateReqVO reqVO) {
        try {
            {OtherDomain}RespDTO data = {otherModule}Api.get{Domain}(reqVO.get{Field}Id());
            // 业务逻辑
        } catch (Exception e) {
            log.error("调用{其他模块}服务失败", e);
            throw exception({DOMAIN}_CREATE_ERROR);
        }
    }
}
```

**❌**** 错误示例**：

```java
@Service
public class {Domain}Service {
    
    @Resource
    private {OtherModule}ServiceImpl {otherModule}Service;  // ❌ 直接依赖实现类
    
    public void create{Domain}({Domain}CreateReqVO reqVO) {
        {otherModule}Service.get{Domain}(...);  // ❌ 跨模块直接调用
    }
```

## 八、数据库设计规范
### 8.1 命名规范
**表命名**：

+ 前缀：`{module}_`
+ 格式：`{module}_{业务域}_{实体}`
+ 示例：`art_work`、`art_pay_order`、`art_user_work`

**字段命名**：

+ 使用下划线分隔
+ 布尔字段：`is_xxx`
+ 时间字段：`xxx_time`
+ 状态字段：`status`
+ 金额字段：`xxx_price`/`xxx_amount`（单位：分）

### 8.2 数据类型选择
| 数据类型 | MySQL类型 | 说明 |
| --- | --- | --- |
| 主键 | BIGINT | 统一使用BIGINT，支持大数据量 |
| 金额 | INT | 单位：分，避免精度丢失 |
| 布尔 | TINYINT | 0-否，1-是 |
| 枚举 | TINYINT/INT | 使用整数存储 |
| 时间 | DATETIME | 精确到秒 |
| 文本 | VARCHAR/TEXT | 根据长度选择 |
| JSON | JSON | 存储复杂对象 |


### 8.3 公共字段
每个表都包含以下公共字段：

```sql
CREATE TABLE {module}_{table_name} (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
    
    -- 业务字段
    -- ...
    
    -- 公共字段
    creator VARCHAR(64) DEFAULT '' COMMENT '创建者',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updater VARCHAR(64) DEFAULT '' COMMENT '更新者',
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted TINYINT NOT NULL DEFAULT 0 COMMENT '是否删除(0-否 1-是)',
    tenant_id BIGINT NOT NULL DEFAULT 0 COMMENT '租户ID'
) COMMENT='{表说明}';
```

### 8.4 索引设计
**索引类型**：

+ **主键索引**：所有表都有自增主键
+ **唯一索引**：业务唯一标识（如订单号）
+ **普通索引**：外键字段、查询条件字段
+ **组合索引**：遵循最左前缀原则

**索引设计原则**：

1. **选择性原则**：高选择性字段建索引
2. **最左前缀**：组合索引遵循最左前缀原则
3. **避免过度**：不要为每个字段都建索引
4. **覆盖索引**：查询字段尽量被索引覆盖

### 10.2 参数校验最佳实践

### 10.3 代码分层与职责划分
**分层职责**：

+ **Controller层**：接收请求、参数校验、调用Service、返回响应
+ **Service层**：业务逻辑、事务管理、数据校验、调用Mapper
+ **Mapper层**：数据访问、SQL执行

**❌**** 错误示例**：

```java
@PostMapping("/{domain}")

    // ❌ 业务逻辑不应该写在Controller中
    {Domain}DO {domain}DO = new {Domain}DO();
    {domain}DO.set{Field}(reqVO.get{Field}());
    
    // ❌ 直接操作Mapper
    {domain}Mapper.insert({domain}DO);
    
    return success({domain}DO.getId());
}
```

**✅**** 正确示例**：

```java
@PostMapping("/{domain}")
public CommonResult<Long> create{Domain}(@Valid @RequestBody {Domain}CreateReqVO reqVO) {
    return success({domain}Service.create{Domain}(reqVO));
}

@Service
public class {Domain}ServiceImpl implements {Domain}Service {
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public Long create{Domain}({Domain}CreateReqVO reqVO) {
        // 业务逻辑在Service层
        {Domain}DO {domain}DO = BeanUtils.toBean(reqVO, {Domain}DO.class);
        validate{Domain}({domain}DO);
        {domain}Mapper.insert({domain}DO);
        return {domain}DO.getId();
    }
}
```

### 10.4 批量查询优化
**避免N+1问题**：

```java
// ❌ 错误：N+1问题
public List<{Domain}RespVO> get{Domain}List(List<Long> ids) {
    List<{Domain}RespVO> result = new ArrayList<>();
    for (Long id : ids) {
        {Domain}DO {domain}DO = {domain}Mapper.selectById(id);  // N次查询
        {RelatedDomain}DO related = relatedMapper.selectById({domain}DO.get{Field}Id());  // N次查询
        result.add(convert({domain}DO, related));
    }
    return result;
}

// ✅ 正确：批量查询
public List<{Domain}RespVO> get{Domain}List(List<Long> ids) {
    // 1. 批量查询主表（1次）
    List<{Domain}DO> {domain}List = {domain}Mapper.selectBatchIds(ids);
    
    // 2. 提取关联ID
    List<Long> relatedIds = {domain}List.stream()
        .map({Domain}DO::get{Field}Id)
        .distinct()
        .toList();
    
    // 3. 批量查询关联表（1次）
    List<{RelatedDomain}DO> relatedList = relatedMapper.selectBatchIds(relatedIds);
    Map<Long, {RelatedDomain}DO> relatedMap = 
        CollectionUtils.convertMap(relatedList, {RelatedDomain}DO::getId);
    
    // 4. 组装数据
    return {domain}List.stream()
        .map({domain}DO -> convert({domain}DO, relatedMap.get({domain}DO.get{Field}Id())))
        .toList();
}
```

## 十二、总结
### 12.1 核心设计原则
1. **单一职责原则**：每个类、每个方法职责单一
2. **开闭原则**：对扩展开放，对修改关闭
3. **依赖倒置原则**：依赖接口而非实现
4. **接口隔离原则**：接口粒度合理
5. **高内聚低耦合**：模块内部高内聚，模块之间低耦合

### 12.2 架构优势
1. **清晰的分层架构**：Controller、Service、DAL各司其职
2. **模块化设计**：API模块和Server模块分离，便于维护和扩展
3. **高内聚低耦合**：业务域划分合理，模块间依赖清晰
4. **可扩展性强**：预留扩展点，支持业务快速迭代
5. **规范统一**：命名规范、代码规范统一，便于团队协作

### 12.3 适用场景
本文档的架构设计和代码结构规范适用于：

+ ✅ 中大型企业级应用
+ ✅ 微服务架构项目
+ ✅ Spring Boot项目
+ ✅ 多模块Maven项目
+ ✅ 需要长期维护和扩展的项目

### 12.4 使用建议
1. **理解设计思想**：先理解设计背后的原理，再关注技术细节
2. **结合实际业务**：根据项目实际情况灵活运用，不要生搬硬套
3. **逐步应用**：从简单场景开始实践，逐步应用到复杂场景
4. **持续优化**：根据项目发展不断优化和调整设计
